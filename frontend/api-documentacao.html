Como começar

A URL base é /api/v1, no mesmo endereço do site. Em desenvolvimento: http://localhost:3000/api/v1. Corpos de requisição vão em JSON, com Content-Type: application/json.

curl http://localhost:3000/api/v1/status
  • Datas em ISO 8601, em UTC: 2026-11-06T12:06:14Z.
  • Limite de 60 requisições por minuto por IP (V1_LIMITE_POR_MINUTO) e de 10 logins por minuto por IP, com contador próprio.
  • CORS liberado para as origens de CORS_ORIGENS (padrão: todas). Sem credenciais.

Respostas e erros

Toda resposta tem o campo success.

{ "success": true, "data": { ... } }
{ "success": true, "mensagem": "Perfil atualizado com sucesso.", "data": { ... } }
{ "success": false, "erro": "Livro não encontrado." }
StatusQuando
400JSON inválido ou URL malformada
401Sem token, token inválido ou vencido, e-mail ou senha incorretos
403Conta desativada, senha provisória pendente ou reserva de outra pessoa
404Rota ou registro inexistente
405Método não aceito na rota; o cabeçalho Allow lista os aceitos
409Conflito de regra: livro sem exemplar, limite de reservas, renovação recusada
413Corpo da requisição grande demais
422Dado recusado pela validação

500Erro interno

Autenticação

Faça login, guarde o token e envie-o nas rotas protegidas no cabeçalho Authorization: Bearer SEU_TOKEN.

  • O token aparece uma única vez, na resposta do login. O servidor guarda só o hash dele.
  • Vale por 7 dias. Depois disso, faça login de novo.
  • Um token por dispositivo: novo login com o mesmo device_name (padrão app) substitui o anterior.
  • Trocar a senha, ter a senha redefinida pela coordenação ou ter a conta desativada derruba os tokens e as sessões do site. Só a credencial usada na própria requisição continua valendo.
  • O cookie de sessão do site não vale aqui, e o token não vale na API do site.
  • Conta com senha provisória (trocar_senha: true) pode entrar, ver o perfil, trocar a senha e sair. Qualquer outra rota protegida responde 403.
  • Tentativas erradas contam no mesmo bloqueio do site: 5 por e-mail e 50 por IP em 15 minutos.

POST /api/v1/auth/login

Público. Corpo: email, senha e, opcional, device_name (até 100 caracteres).

curl -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"beatriz.lima@fpsf.edu.br","senha":"SUA_SENHA","device_name":"celular"}'
{
  "success": true,
  "mensagem": "Login realizado com sucesso.",
  "data": {
    "token": "SEU_TOKEN",
    "usuario": { "id": 2, "nome": "Beatriz Lima", "email": "beatriz.lima@fpsf.edu.br",
                 "papel": "aluno", "turma": "8º ano B", "trocar_senha": false }
  }
}

E-mail inexistente e senha errada recebem a mesma resposta: 401 “E-mail ou senha incorretos.”. Conta desativada: 403.

POST /api/v1/auth/logout

Token. Apaga só o token usado na requisição.

{ "success": true, "mensagem": "Logout realizado com sucesso." }

GET /api/v1/materias/:slug/livros

Os livros da matéria, no formato de /livros. Matéria inexistente: 404 “Matéria não encontrada.”.

GET /api/v1/livros

Filtros opcionais: ?materia=slug e ?busca=texto. A busca ignora acentos e maiúsculas, no título e no autor.

{ "success": true, "data": [ {
  "id": 3, "slug": "dom-quixote", "titulo": "Dom Quixote", "autor": "Miguel de Cervantes",
  "materia_slug": "literatura", "capa": "domQuixote.jpg", "sinopse": "...", "paginas": 863,
  "idioma": "Português", "materia_nome": "Literatura", "materia_icone": "livro.png",
  "total_exemplares": 2, "disponiveis": 2
} ] }

A capa fica em /assets/<capa>.

GET /api/v1/livros/:slug

Um livro, no mesmo formato. Inexistente: 404 “Livro não encontrado.”.

GET /api/v1/usuario

Token. Vale também com senha provisória.

{ "success": true, "data": { "id": 2, "nome": "Beatriz Lima", "email": "beatriz.lima@fpsf.edu.br",
  "papel": "aluno", "turma": "8º ano B", "trocar_senha": false } }

PUT /api/v1/usuario

PATCH /api/v1/usuario

Token. Muda só nome (até 80) e email (válido, até 120, único). O PUT exige os dois; o PATCH valida só o que vier. Outros campos são ignorados.

curl -X PATCH http://localhost:3000/api/v1/usuario \
  -H "Authorization: Bearer SEU_TOKEN" -H "Content-Type: application/json" \
  -d '{"nome":"Bia Lima"}'
{ "success": true, "mensagem": "Perfil atualizado com sucesso.", "data": { ... } }

E-mail de outra conta: 422 “Já existe um usuário com esse e-mail.”.

PUT /api/v1/usuario/senha

Token. Vale também com senha provisória. Corpo: senha_atual, nova_senha (ao menos 8 caracteres, diferente da atual) e nova_senha_confirmation.

{ "success": true, "mensagem": "Senha alterada com sucesso." }

Senha atual errada: 422 “Senha atual incorreta.”, e a tentativa conta no bloqueio. Os outros tokens e as sessões do site caem; o token atual continua.

Reservas e Quero ler

Com token e com a senha já trocada. Valem as mesmas regras do site, sempre sobre as reservas de quem é dono do token. Estas rotas não existem na versão Laravel.

GET /api/v1/reservas

{ "success": true, "data": [ {
  "id": 12, "status": "retirada", "criada_em": "2026-11-01T12:00:00Z", "expira_em": "2026-11-04T12:00:00Z",
  "encerrada_em": null, "retirada_em": "2026-11-02T12:00:00Z", "devolver_ate": "2026-11-16T12:00:00Z",
  "renovacoes": 0, "atrasada": false, "pode_renovar": true, "novo_prazo": "2026-11-23T12:00:00Z",
  "exemplar_codigo": "DOM-QUIX-001", "livro_slug": "dom-quixote", "titulo": "Dom Quixote",
  "autor": "Miguel de Cervantes", "capa": "domQuixote.jpg"
} ] }

status: ativa (aguardando retirada), retirada, devolvida ou cancelada.

POST /api/v1/reservas

Corpo: { "livro_id": 3 }. Responde 201 com a reserva em data. Até 3 reservas simultâneas por aluno; a pré-reserva vale por 3 dias.

POST /api/v1/reservas/:id/cancelar

Só a própria reserva e ainda não retirada.

POST /api/v1/reservas/:id/renovar

Soma 7 dias ao prazo. Só livro retirado, sem atraso e uma vez por empréstimo.

GET /api/v1/favoritos

Os livros da lista “Quero ler”, no formato de /livros, o mais recente primeiro.

PUT /api/v1/favoritos/:livroId

DELETE /api/v1/favoritos/:livroId

Adiciona e remove. Repetir a operação não é erro.
